### 適用可能性と法務確認が必要な事項（適合を保証しない）

- **韓国PIPA**: 韓国居住者向け広告のため域外適用の可能性。行動情報（Cookie等）の収集・広告利用の告知、国外移転（移転先・項目・目的・期間・拒否方法）の告知／同意、個人情報保護責任者の公開（反映済み）、委託・処理の告知。2022年にGoogle・Metaが行動情報の収集で韓国当局の処分を受けた経緯があり、Cookie等の扱いは慎重な確認が必要。
- **タイPDPA**: 事業者がタイ法人のため適用可能性が高い。Cookie等の識別子の同意、越境移転の要件、データ管理者の連絡先、権利行使の手順。
- **日本の個人情報保護法**: 日本居住者向けの場合。Cookie IDなどの個人関連情報の第三者提供時の確認義務、外国にある第三者への提供時の情報提供。電気通信事業法の外部送信規律（対象サービスか要確認）。
- **EU/UK（GDPR・ePrivacy）**: 欧州居住者を対象とする場合、非必須Cookieは事前同意が必要。

### G-2. 同意管理が必要となる条件（要法務確認）
- 欧州（EU/UK）居住者を対象にする、または実際に流入する場合 → 非必須Cookie・計測は事前同意が原則。
- タイ → PDPAにより識別子の取得に同意（または他の適法根拠）が必要とされる可能性。
- 韓国 → 行動情報の収集・利用の告知とオプトアウト手段（および案件によっては同意）が必要となる可能性。
- 日本 → 外部送信規律（対象サービスの場合は通知・公表、オプトアウト）、個人関連情報の第三者提供規制。
- 広告配信先が韓国中心でも、閲覧者の居住地は韓国に限らない。→ **地域別の挙動（EU/UKのみ事前同意、その他はバナー＋拒否可）**が現実的な折衷案。

### G-3. 同意管理を導入した場合の計測への影響
| 項目 | 影響 |
|---|---|
| Meta Pixel | 拒否時は `fbq('consent','revoke')` 等で停止／遅延。拒否ユーザーのイベントは計測されず、広告最適化の学習母数が減る可能性 |
| Meta CAPI | サーバー側でも同意状態に従う必要がある。現状の実装は同意状態を受け取らないため、導入時は `contact` ルートに同意フラグを渡す改修が必要（既存の event_id・重複排除は維持可能） |
| GA4／GTM | Googleの同意モード（Consent Mode v2: ad_storage / analytics_storage / ad_user_data / ad_personalization）に対応。拒否時もCookieなしのpingによるモデリングで一部補完可能 |
| Clarity | Clarityの同意シグナル対応。欧州向けでは同意シグナルが必須化されたとの案内がある（要確認） |
| 同意拒否時のコンバージョン | 拒否率に比例して観測コンバージョンが減少。広告の最適化は観測できたイベントで学習するため、拒否率が高いとCPA悪化の可能性 |

### G-4. 広告最適化をできるだけ維持する実装案
1. 現在の計測タグ構成・イベント名・`event_id` は変更せず、GTMのConsent Modeで「同意状態による発火制御」のみ追加する。
2. 地域別の初期状態: EU/UK/スイスは拒否が既定（事前同意）、その他の地域は許可が既定＋バナーで拒否可能（法務確認が前提）。
3. バナーUIの構成案:
   - 「すべて許可」「必要なもののみ許可」「詳細設定（必須／解析：GA4・Clarity／広告：Meta Pixel・CAPI）」
   - フッターに常設の「Cookie設定」リンクで同意内容を後から変更
4. CAPIは、同意フラグがある場合のみ送信する（導入時に `contact` ルートを小改修）。
5. 事前に本番で計測を壊さないよう、ステージングまたはGTMプレビューで、Pixelの `Lead` / `FormSubmit` と `event_id` の重複排除を確認してから公開する。
